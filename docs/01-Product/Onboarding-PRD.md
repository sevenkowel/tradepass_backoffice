## 1. 背景与目标 (WHY)

### 1.1 业务问题

当前用户注册后的体验：

```
注册成功 → Console 首页（空荡荡） → 看到「创建租户」按钮 → 点击进入向导 → 创建完成 → 看到租户详情
```

**核心问题：**

| # | 问题 | 影响 |
|---|------|------|
| 1 | 注册后无引导，用户进入空的 Console | 大量用户在创建租户前流失 |
| 2 |「创建租户」是 4 步配置表单，不是「开业流程」 | 用户感觉在填表，没感受到价值 |
| 3 | 无完成标准，用户不知道什么叫「可用」 | 配置完后无获得感 |
| 4 | 无渐进解锁，所有功能要么全有要么全无 | 无法驱动用户完成初始化 |
| 5 | 无付费转化设计，初始化与付费脱节 | 完成初始化后不知道怎么引导付费 |

### 1.2 业务目标

| 指标 | 当前 | 目标 |
|------|------|------|
| 注册→租户创建转化率 | 未知（无数据） | > 60% |
| 初始化完成率（7天内） | 0（无概念） | > 40% |
| 初始化完成 → 付费转化率 | 0（无概念） | > 15% |
| 平均初始化耗时 | 10-15 分钟 | < 5 分钟 |

### 1.3 核心设计原则

```
1. 不阻止探索，但阻止变现能力
   → 可以看 Demo，不能收款/交易

2. 初始化 = 价值体验，不是填表
   → 每一步都要让用户看到成果

3. 把「收款配置」作为核心转化点
   → 这是付费开关，也是用户第一次感知价值
```

## 2. 初始化配置体系

### 2.1 三层分级架构

将 10 个配置模块分成三层，不同层级对应不同的推进策略：

```
Phase 1：必须配置（最小可用经纪商）
├─ ① Branding & Site     品牌站点
├─ ② Auth & User         用户认证
├─ ③ KYC Workflow        开户流程
├─ ④ Payments ⭐         资金系统（核心转化点）
├─ ⑤ Trading Config      交易配置
└─ ⑥ Account Types       账户类型

Phase 2：建议配置（触发付费）
├─ ⑦ Notifications       通知系统
├─ ⑧ Domain & Access     域名绑定（付费卡点）

Phase 3：高级运营（付费解锁）
├─ ⑨ Risk Control        风控策略
├─ ⑩ Portal & Growth     Portal 定制 / AI 信号
```

### 2.2 模块详细定义

#### Phase 1 — 必须配置（6 项）

##### ① Branding & Site（品牌站点）✅ 必须

**目的：** 回答「你的平台长什么样」

| 字段 | 必填 | 说明 |
|------|------|------|
| 品牌名称 | ✅ | 显示在 Portal/CRM 中 |
| Logo（深浅色） | ✅ | 支持上传预览 |
| 公司全称 | ✅ | 法律实体名称 |
| 子域名 | ✅ | 系统自动分配 (xxx.tradepass.io) |
| 品牌主色 | ✅ | 预设 6 色 + 自定义 |
| Favicon | 可选 | 浏览器标签图标 |
| Slogan | 可选 | 品牌标语 |

**价值点：** 创建品牌 → 即时生成 Portal 预览 → 用户感受到「这是我的平台」

---

##### ② Auth & User（用户认证）✅ 必须

**目的：** 回答「用户怎么进来」

| 字段 | 默认值 | 说明 |
|------|--------|------|
| 注册方式 | Email | Email / 手机 / 两者皆可 |
| 邮箱验证 | 开启 | 注册时是否发送验证邮件 |
| 登录方式 | 密码 | 密码 / OTP / 两者皆可 |
| 国家选择 | 自动检测 | 注册时的国家选择逻辑 |
| 注册字段 | 姓名+邮箱+国家 | 用户注册时必填的字段 |

**MVP 默认：** 提供「极简注册模式」（仅邮箱+密码），降低注册门槛

---

##### ③ KYC Workflow（开户流程）✅ 必须

**目的：** 回答「用户能不能交易」

| 字段 | 默认值 | 说明 |
|------|--------|------|
| KYC 等级 | Standard | Basic / Standard / Enhanced |
| 身份认证方式 | 身份证+人脸 | KTP / Passport / 驾照 |
| 地址证明 | 关闭 | 可选开启 |
| 活体检测 | 开启 | Liveness 检测 |

**模板选择：**
- **国际简版**（MVP 默认）：身份证 + 人脸
- **印尼 OJK 版**：KTP + NPWP + 地址证明
- **高合规版**：护照 + 地址证明 + 视频验证

---

##### ④ Payments ⭐（资金系统）**核心转化点**

**目的：** 回答「你怎么收钱」

| 配置项 | 说明 |
|--------|------|
| 入金方式 | 至少 1 个（强引导） |
| 提款方式 | 可后置 |
| 最低/最高金额 | 渠道级别配置 |
| 手续费 | 固定金额或百分比 |
| 处理时间 | 即时 / 1-2 工作日 |
| 通道路由 | 自动路由策略（高级） |

**MVP 支持的渠道：**

| 渠道 | 类型 | 适用地区 |
|------|------|----------|
| 本地银行转账 | 入金+出金 | 国际 |
| BCA / Mandiri | 入金 | 印尼 |
| DANA / OVO | 入金 | 印尼 |
| USDT (TRC20/ERC20) | 入金+出金 | 国际 |
| Visa/Mastercard | 入金 | 国际 |

> ⚠ **关键设计：** 初始化时必须强引导完成至少 1 个入金方式。这是用户第一次感知到「可以赚钱了」。

---

##### ⑤ Trading Config（交易配置）✅ 必须

**目的：** 回答「你怎么赚钱」

| 字段 | 默认值 | 说明 |
|------|--------|------|
| 交易产品 | 外汇+贵金属+指数 | 可选：外汇/黄金/指数/Crypto |
| 杠杆默认值 | 1:100 | 可配置范围 |
| 点差模式 | 浮动点差 | 固定 / 浮动 / 原始+佣金 |
| 交易模式 | STP | STP / B-Book（高级） |

> **设计原则：** 提供「标准模板」，不要让用户从零配置

---

##### ⑥ Account Types（账户类型）✅ 必须

**目的：** 回答「用户用什么账户交易」

| 字段 | 默认值 |
|------|--------|
| 账户类型 | Standard + ECN |
| 最低入金 | $100 (Standard) / $500 (ECN) |
| 杠杆范围 | 1:50 ~ 1:500 |
| 是否允许对冲 | 开启 |

---

#### Phase 2 — 建议配置（2 项）

##### ⑦ Notifications（通知系统）🟡 半必须

| 配置 | 默认 | 说明 |
|------|------|------|
| 邮件 | TradePass 默认 | 免费，有发送限额 |
| 短信 | TradePass 默认 | 免费，有发送限额 |
| 站内通知 | 开启 | 免费 |

**MVP 策略：** 默认开启 Email（最低成本），无需用户配置

##### ⑧ Domain & Access（域名绑定）🟡 **付费卡点**

| 配置 | 说明 |
|------|------|
| 子域名 | ✅ 系统自动分配（免费） |
| 自定义域名 | 💰 **付费解锁**（Pro 套餐） |
| SSL 证书 | 💰 自动配置 |

> **转化设计：** 自定义域名 = 付费功能。当用户完成初始化后，提示升级以绑定自己的域名。

---

#### Phase 3 — 高级运营（付费解锁）

##### ⑨ Risk Control（风控策略）

| 功能 | 说明 |
|------|------|
| 大额入金触发 Video KYC | ✅ 默认开启 |
| 提款限制 | ✅ 默认有规则 |
| 多账户限制 | ✅ 默认有限制 |
| EA 套利识别 | 💰 Pro 套餐 |
| 异常交易风控 | 💰 Pro 套餐 |

##### ⑩ Portal & Growth（Portal 定制）

| 功能 | 说明 |
|------|------|
| Dashboard 组件选择 | ✅ 免费 |
| 首次用户引导 | ✅ 免费（模板） |
| 活动位 / Banners | 💰 Pro 套餐 |
| AI Trading Signals | 💰 Pro 套餐 |

## 3. 初始化状态机

### 3.1 租户状态定义

```typescript
type OnboardingStatus =
  | 'not_started'   // 注册完成，未开始初始化
  | 'in_progress'   // 正在进行中
  | 'completed'     // Phase 1 全部完成
  | 'paused';       // 用户主动暂停

type OnboardingPhase = {
  branding: boolean;     // Phase 1 - 品牌站点
  auth: boolean;         // Phase 1 - 用户认证
  kyc: boolean;          // Phase 1 - KYC 流程
  payments: boolean;     // Phase 1 - 资金配置 ⭐
  trading: boolean;      // Phase 1 - 交易配置
  accounts: boolean;     // Phase 1 - 账户类型
};
```

### 3.2 初始化完成标准

用户完成以下 5 项检查清单后，标记为 `completed`：

```
✅ 品牌已创建
✅ 用户可注册
✅ 可完成 KYC
✅ 可入金（至少 1 个渠道）
✅ 可创建交易账户

→ 🎉 "你的经纪商已上线"
```

### 3.3 状态流转图

```
注册成功
  │
  ▼
not_started ──→ 用户点击「开始引导」──→ in_progress
  │                                          │
  │  用户选择「稍后继续」                      ├── 完成 Phase 1 → completed
  │                                          │                     │
  ▼                                          └── 用户退出 → paused  │
paused ──→ Dashboard 顶部显示进度条                                 │
          关键功能被拦截                                              ▼
                                                              Dashboard 展示
                                                              庆祝页面 + 付费引导
```

## 6. 付费转化设计

### 6.1 三个转化卡点

#### 卡点 1：完成初始化 → 提示升级

**触发时机：** 用户刚刚完成初始化（Phase 1）

**弹窗内容：**
```
┌──────────────────────────────────────┐
│  🎉 恭喜！你的经纪商已准备就绪       │
│                                      │
│  升级套餐以启用真实业务:              │
│  • 真实入金通道                      │
│  • 提款功能                          │
│  • 自定义域名                        │
│  • 更多交易产品                      │
│                                      │
│  [升级至 Starter]   [稍后考虑]       │
└──────────────────────────────────────┘
```

#### 卡点 2：开启真实存款 → 付费墙

**触发时机：** 用户在支付设置页点击「启用」存款通道

```
┌──────────────────────────────────────┐
│  💰 升级套餐以启用真实入金            │
│                                      │
│  免费版使用 Demo 资金，不能提现       │
│  Starter 套餐支持:                    │
│  • 真实入金（银行转账/ Crypto）      │
│  • 客户提款                          │
│  • 专属技术支持                      │
│                                      │
│  [升级仅需 $99/月]   [了解详情]      │
└──────────────────────────────────────┘
```

#### 卡点 3：自定义域名 → 付费墙

**触发时机：** 用户访问域名设置页

```
┌──────────────────────────────────────┐
│  🌐 自定义域名为增值功能               │
│                                      │
│  可用套餐：                           │
│  • Starter：基础域名                  │
│  • Pro：自定义域名 + SSL             │
│  • Enterprise：多域名 + CDN          │
│                                      │
│  [查看定价]   [继续使用子域名]        │
└──────────────────────────────────────┘
```

### 6.2 套餐定价结构（建议）

| 套餐 | 价格 | 核心能力 | 目标用户 |
|------|------|----------|----------|
| Free | $0 | Demo 平台、预览、模板配置 | 探索期用户 |
| Starter | $99/月 | 真实收款、基础交易、10 用户 | 小型经纪商 |
| Pro | $299/月 | 自定义域名、高级 KYC、EA 风控 | 成长型经纪商 |
| Enterprise | 定制 | 全功能、私有部署、SLA | 大型机构 |

### 7.2 设计风格

沿用力控设计系统（现有 CSS 变量）：

- 背景：`--tp-bg` (#F5F7FA)
- 表面：`--tp-surface` (#FFFFFF)
- 主色：`--tp-accent-rgb` (30, 64, 175)
- 文字：`--tp-fg-rgb` (31, 41, 55)

每种状态的颜色语义：
- `not_started` / 未完成：粉色 / 琥珀色
- `in_progress` / 进行中：蓝色
- `completed` / 已完成：绿色
- 付费提示：紫色 / 琥珀色

### 7.3 文案风格

| 场景 | 原则 | 示例 |
|------|------|------|
| 引导页 | 情绪价值 | 「启动你的经纪商」而不是「创建租户」 |
| 步骤 | 成果导向 | 「你的专属交易平台已创建 🎉」 |
| 收款 | 价值感知 | 「完成配置，开始接收客户入金」 |
| 完成 | 成就感 | 「你的经纪商已上线！」 |
| 拦截 | 低阻碍 | 「仅需 2 分钟即可解锁」 |

## 8. 数据埋点

### 8.1 核心事件

| 事件 | 触发时机 | 用途 |
|------|----------|------|
| `onboarding_started` | 用户点击「开始」 | 漏斗入口 |
| `onboarding_step_completed` | 每步完成 | 步骤转化 |
| `onboarding_paused` | 中途退出 | 流失分析 |
| `onboarding_completed` | 全部完成 | 核心指标 |
| `feature_blocked` | 功能被拦截 | 拦截触发率 |
| `feature_blocked_click_continue` | 拦截弹窗点「立即完成」 | 引导效果 |
| `onboarding_to_pricing` | 点击升级套餐 | 付费转化入口 |

## 10. 附录

### 10.1 与现有架构的兼容性

| 现有组件 | 是否需要修改 | 改动方式 |

### 10.2 风险与缓解

| 风险 | 可能性 | 影响 | 缓解方案 |
|------|--------|------|----------|
| 用户感觉被强制 | 中 | 高 | 提供「稍后继续」，Demo 数据仍可见 |
| 多租户用户困惑 | 低 | 中 | 首租户强制引导，之后正常进入 Console |
| 支付配置太复杂 | 中 | 中 | 模板预设 + 强推荐 |
| 完成标准不明确 | 低 | 中 | 明确的 5 项检查清单 |
