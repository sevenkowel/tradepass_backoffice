# 审核队列与 Cases 优化

> 日期：2026-05-11 · 分类：产品文档 · 状态：已确认

## 决策一：Review Queue 只展示 KYC 相关审核

存款 / 取款 / 交易异常 → 不该出现在合规审核队列。详细落地见 `2026-05-11-CLM模块定位.md`。本文档只记录 Review Queue 自身的相关行为：

- 列表数据源已经天然干净（CLM CaseType 不含 withdrawal_review）
- 顺手删除了原先在页面里手写的 `KYC_CASE_TYPES` 锁定常量 —— 类型系统已经做了同样的事，留下来反而是冗余
- `CaseListParams.typeIn` 能力保留（已经实现），将来 Treasury / Risk 模块自己的队列页能复用同一个 case service

## 决策二：Cases 页区分自动 / 人工审批

运营提出："能不能一眼看到哪些是引擎自动处理的，哪些是人工审批的？"

### 数据来源

复用已有的 `CLMCaseStatus`：
- `auto_approved` / `auto_rejected` → 自动决策
- `approved` / `rejected` → 人工决策（同时 `reviewedBy` 字段记录审核人姓名）
- `pending / reviewing / escalated / resubmission` → 尚未终结

不增加冗余字段（不需要 storage-level 的 `decisionMode`），用衍生函数 `decisionModeOf(c)` 即可。

### 列与筛选

**新增列 Decision**（在 Status 和 SLA 之间）：
- Auto — 紫色芯片 + Bot 图标；tooltip 显示 `reviewReason`（如有）
- 审核人姓名 — 蓝色芯片 + User 图标；tooltip 显示"Reviewed by …"
- `—` — 灰色破折号占位

**新增筛选 Decision**：
- 选 Auto → service 内部把 `decisionMode` 翻译为 `status in {auto_approved, auto_rejected}`
- 选 Manual → `status in {approved, rejected}`
- 选 Pending → `status in {pending, reviewing, escalated, resubmission}`

### 服务接口

```
CaseListParams.decisionMode?: "auto" | "manual" | "pending"
```

在 `case.service.ts` 内部转换成状态集合后做 filter；保持 service 抽象。

### Mock 数据补充

- 给原 `case-019` 补 `reviewedBy: "System"` + `reviewedAt`
- 新增 `case-019b`（auto_approved，洁净信号）
- 新增 `case-019c`（auto_rejected，AML hit / OFAC SDN 匹配）

让筛选 / 列在 demo 中能展示多样性。
