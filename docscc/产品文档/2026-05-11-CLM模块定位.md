# CLM 模块定位

> 日期：2026-05-11 · 分类：产品文档 · 状态：已确认

## 核心结论

**CLM = 用户资料合规审核域**。存款、取款、交易异常这些金融操作的处理流程，不归属 CLM；它们属于未来的 Treasury 或 Risk 模块。

## 边界定义

| 归属 CLM | 不归 CLM |
|---|---|
| KYC 提交审核 | 取款审核（Treasury） |
| POA / 地址证明 | 存款审核（Treasury） |
| 活体验证 | 交易异常处置（Risk） |
| 视频认证 | |
| EDD 增强尽调 | |
| 资金来源证明 (SoW) | |
| 协议签署审核 | |
| 风控触发的 KYC 复查（risk_recheck） | |
| 人工审核兜底（manual_review） | |
| 再认证（re_verification） | |

## 设计原则

CLM 只接收"动作 = 审核身份/资料"的案件；像"大额存款"这样的事件可以**触发**一次 CLM 复查（如视频验证），但触发源是事件，CLM 案件本身写的是合规动作。`triggerSource` 文案必须用合规语言，不要用财务语言。
