## 一、核心审批工作流（Core Workflow）

> 范围：`review-queue` / `cases/[id]` / `workspace` + `case.service.ts` + 各 popover / RichTimeline / DocumentPreview

| P0 | `approve(undefined)` → `updateCaseStatus(reason=undefined)` 覆盖原有 `reviewReason` | `cases/[id]/page.tsx:124,1337` + `case.service.ts:320-322,410-427` |

### A.2 功能 / 流程 Bug（P1）

- **`assign()` 写死 assigneeName**：`assigneeId==="staff-001"?"Admin A":...:"Senior Reviewer"`；任何真实 ID 都被改名 — `case.service.ts:360-366`
- **没有乐观锁 / 版本号**：两人并发 approve 同一 case，后者覆盖前者 — `case.service.ts:320-354`
- **`getMyTasks` 用真实 `userId`，但 `assignee=me` filter 硬编码 `staff-001`** — `case.service.ts:114-116,310-317`
- **`requestResubmission` 不更新 `updatedAt`** — `case.service.ts:330-341`
- **`escalate` / `requestResubmission` 设置 `reviewedAt/reviewedBy`**，把升级误标记为"已决策" — `case.service.ts:330-354`
- **Take-over 不做 etag 检查**，他人已接单的 case 仍可"接过来" — `cases/[id]/page.tsx:1539-1546`
- **`canEscalate = isKYC && escalatableSteps.length > 0`**：非 KYC 类型完全没"手动升级"通道
- **`videoChecks` 本地状态从不发送到任何后端**：reviewer 勾的 6 项 checklist 不持久化 — `cases/[id]/page.tsx:75,96-100,462-465`

### A.3 UI / UX 问题

#### P0 — Case Detail 中文残留（i18n 半成品）
- `cases/[id]/page.tsx:470` `协议签署详情`
- `:578-749` Liveness / POA / Video 区块所有文案
- `:1013,1044` "注册时 / 开户时"
- `:1175` `审核人：`
- `DocumentPreview.tsx:221-263` `姓名/证件号码/国籍/出生日期/有效期至/OCR 提取/用户提交/已修改`
- `AgreementSection.tsx:58,68,86,102` `预览 / 协议已更新 / 签署于 / 暂无可预览的文件`
- `case.service.ts:485-490` Video checklist labels 全中文

#### P0 — 视觉一致性
- **Case Detail 用页面内的 `StatusBadge`**（line 1638），不是 Review Queue 用的 `BadgeBase`，视觉不一致 — `cases/[id]/page.tsx:226,1638-1670`
- **Take Over 蓝色与 Approve 绿色同强度**：pending case 看起来"接管"和"批准"重要性相同 — `cases/[id]/page.tsx:1539-1546,1569-1574`
- **Hover-only popover 在触屏完全用不了**：`HoverPopover / IPGeoPopover / IBSummaryHover` 三处都只用 `onMouseEnter/Leave`，没有 `onFocus/onBlur` 或 click 兜底 — 多文件
- **右栏 sticky 但无内部 overflow**：Timeline 多于 ~20 条事件时，底部被永久遮挡 — `cases/[id]/page.tsx:349`
- **底部 bar 与 sticky 右栏共占空间**：右栏底部 ~56px 永远在底栏之下，看不到 — `cases/[id]/page.tsx:190,1500-1503`

#### P1 — 其它视觉
- Z-index 冲突：DocumentPreview 灯箱 `z-50` 低于 popover `z-100`，灯箱开着时仍被悬浮浮层覆盖 — `DocumentPreview.tsx:117`
- `STATUS_TEXT` 在 Review Queue（"Auto Approved"）与 Cases page（"Auto-Approved"）字符串不一致
- 决策按钮无快捷键（A/R/S/E）
- `LivenessContent` `✗ 未通过 / ✓ 通过` 用 emoji，不与上下文的 lucide 图标统一

### A.4 数据模型缺陷（非 case-001）

| 问题 | 文件 |
|---|---|
| `customerSnapshot.totalCases=1, pendingCases=0/1` 硬编码 | `case.service.ts:229-232` |
| `kycFlowSteps` 永远 3 included + 3 not，不看 kycLevel | `case.service.ts:441-449` |
| 所有 case 的 `personalInfo.registrationIp = "192.168.1.***"` | `case.service.ts:199-205` |

### A.5 过滤 / 搜索 缺失

- Review Queue 搜索 placeholder 说"case ID / customer name / UID"，但服务端实际还搜 `country` 和 `type` — `case.service.ts:122-133` + `review-queue/page.tsx:443`
- **没有 country / customerTier filter**：`CaseListParams` 支持，UI 不暴露
- **`slaStatus` filter 三档**（normal/near_timeout/timeout），但 `computeSLA` 实际产生五档（含 `critical / warning`）— filter 漏选
- **`Cancelled` 和 `Expired` 颜色同灰**，操作员看不出"用户取消"vs"系统过期" — `review-queue/page.tsx:54-57`

### A.6 性能

- 每 15 秒 SLA tick 触发整页大重渲染：`slaInfo` 是 page state，应该下沉到 SLA 小组件 — `cases/[id]/page.tsx:106-110`
- `BottomActionBar` 所有 props 每次重建（`h={...}` 内联），子组件无 memo — `cases/[id]/page.tsx:388-393,123-136`
- `RichTimeline.events.map` 每事件都建新 `() => onReply(evt.id)` 闭包
- `HoverPopover` 每次渲染重建 `onMouseEnter/Leave`，N 行 N 个

## 五、推荐优先级

### Sprint 0（本周必须修，全是 P0）
1. **实现 audit 日志写入**：在 `caseService` / `flowService` / `agreementService` 所有 mutation 调用 `globalAuditService.log()`；或者把 `withAudit.ts` 真正接起来

5. **ConfigDrawer 加 dirty-state 确认**：基础组件层一次解决所有编辑器丢稿问题
